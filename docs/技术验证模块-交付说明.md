## 二、现场入口

1. 登录页底部「技术验证模块」链接；
2. 「我的」页顶部金色卡片「技术验证模块」；
3. 公开路由 `#/verify`（无需业务账号，不受登录态拦截）。

页面为独立全屏，不叠加业务导航与客服浮窗，四语（中文/English/العربية/کوردی）可随时切换。

## 四、现场操作顺序（建议）

1. 填写执行人、现场地点（导出报告必填）；
2. ENV-01 探测并保存 → 判断机型是否具备 NFC/Play 服务；
3. NFC-01：每张证件读一次，逐张保存，注明发卡批次；
4. OCR-01 / FACE-01 / SPOOF-01：按编号连续采集（卡背必填家庭编号；人脸 S01 起递增）；
5. QR-01：A 机「显示动态码」、B 机「扫码验证」，同码扫两次验证重放拦截，再改系统时间 ±3 分钟复测；
6. BIO-01 / BIND-01 / RTL-01 / GUIDE-01 按步骤人工核验；
7. 每项选择结论（可行 / 有条件可行 / 不可行）并填写备注；
8. 「导出验证报告」→ 系统分享面板选择 WhatsApp / 邮件 / 网盘回传 ZIP。

## 五、导出内容

- `report.md`：中英双语总览表 + 逐项指标（成功率、耗时、状态字分布、样本分布）+ 结论与备注；
- `report.json`：完整数据快照（设备、探测、每条记录与影像路径），供我方离线复算；
- `csv/<用例>.csv`：逐条样本表（含 imageFiles 列），UTF-8 BOM，Excel 可直接打开阿语/库语；
- `evidence/<用例>/*.jpg`：全部影像。

数据只存本机 IndexedDB，不上传服务器；「清空本机数据」可一键清理。报告仅记录现场观察，不构成验收结论。

## 六、已知边界

1. 模块内不含 ArcFace / MediaPipe / OCR / PACE-BAC 模型，人脸与卡面只做「样本采集」，阈值与准确率需我方离线评测；
2. NFC 探测只做 AID 选择与 EF.COM 状态字，不做被动认证与 CSCA 锚定（缺业主主列表）；
3. 扫码双端联调需两台装同一 APK 的手机；
4. debug 签名，正式安装包需按发布签名流程重签。
